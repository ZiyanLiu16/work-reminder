# 回到目标 · Work Reminder

一个仅在本机运行的 Chrome 扩展。在 YouTube、B 站和小红书网页版累计浏览 15 分钟后，以个人目标、项目片段或一句鼓励温和提醒你。

## 本地安装

已构建的扩展位于 `dist/`。不需要服务器、账号、API key 或 npm install。

macOS：双击项目中的 **安装或更新.command**，会构建扩展并打开 Chrome 扩展管理页和 dist 文件夹。首次加载需要在 Chrome 完成：

1. 在 `chrome://extensions` 打开右上角 **Developer mode / 开发者模式**。
2. 点击 **Load unpacked / 加载已解压的扩展程序**。
3. 选择本项目的 **dist** 文件夹（不是项目根目录）。

构建完成后，扩展目录是项目根目录下的 `dist/`。

安装后自动打开带有三步引导的设置页：填写目标、选择本地项目文件夹、添加鼓励帖文链接。每一项都有说明、示例和完成状态。目标必填，后两项可跳过或稍后补充。通过工具栏扩展菜单打开“回到目标”，可以重新进入设置、看当前计时、暂停提醒和启用学习模式。需要时可在 Chrome 扩展菜单中将它固定。用户无需向开发者或聊天助手提供这些内容。

保持 dist 文件夹的位置不变，Chrome 会从这个目录加载扩展。重启 Chrome 后扩展仍安装着，本轮累计重新开始。

## 使用规则

- 只累计 Chrome 前台窗口里当前标签页的目标网站时间；三个网站共同累计。
- 离开不足 5 分钟，保留累计，但不计入离开时间。
- 连续离开满 5 分钟，旧累计清零。B 站 8 分钟 → 工作 40 分钟 → YouTube 7 分钟，只算新一轮 7 分钟。
- 系统输入闲置超过 120 秒时暂停；可见页面中有正常播放的视频时仍计时。锁屏始终暂停。
- “再看 5 分钟”：再累计 5 分钟后提醒；关闭：再累计设定间隔后提醒。
- “回到目标”：打开扩展自己的目标页，重置本轮计时。
- “本标签页学习 60 分钟”：暂时排除此标签页；刷新保留，关闭或浏览器重启后清除。
- 保存目标/间隔、切换暂停状态、增删项目快照都会开始新一轮。

## 项目片段

在设置中选择 1–2 个项目目录，先预览并勾选片段，再保存。

优先 README、TODO、文档，其次源代码。不会执行项目里的任何代码。隐藏文件、常见密钥文件、依赖、构建产物、大文件和非文本文件会被排除。过滤不能识别所有写在普通代码里的敏感内容，请在预览时取消不想展示的片段。

仅保存少量文本快照，不保存整个仓库。每个项目至多 30 个片段，单文件不超过 200 KB，最多读取 100 个候选文件。快照不会自动更新；点击“重新导入”更新。

提醒内容显示在扩展自身 origin 的 iframe 中，网页脚本无法直接读取卡片中的目标和项目文本。扩展没有发送数据到外部服务器的代码。所有设置存储于 `chrome.storage.local`，计时存储于 `chrome.storage.session`；不使用云端同步。

用户在设置页第三步粘贴鼓励帖文链接，可选填写摘录和作者，最多保存 20 条。保存后立即用于第三类提醒，无需修改代码或重新安装。仅填链接时会展示收藏入口，不会假装已经读取原帖；填写摘录后则可直接在提醒中阅读。没有自定义链接时使用内置原创鼓励。开发者也可以编辑 `extension/encouragements.json` 更新内置内容。

## 更新与开发

编辑 `extension/` 后，双击安装脚本，或运行：

```sh
npm run build
```

随后在 `chrome://extensions` 点击该扩展的重新加载按钮，并刷新已经打开的目标网站。设置页也需刷新。扩展重新加载会保留本地目标和项目快照，本轮计时清零。

为减少本地构建步骤，实际实现采用原生 JavaScript ES modules，而非设计提案中的 TypeScript/Vite。生产扩展无第三方依赖；构建只检查 JavaScript 语法并复制到 dist。

## 自动化测试

需要 Node.js 20.11+。首次安装测试依赖（仅 jsdom 及其依赖，不打包到扩展）：

```sh
npm ci
npm run check
npm run test:coverage
```

测试包括计时状态机、消息来源校验、Chrome API 模拟集成、文件导入、提醒轮换、DOM 安全、全屏挂载策略、设置表单与导入预览。测试用模拟时钟跑 5 分钟/40 分钟等边界，不需要真实等待。

`artifacts/test-run.txt` 和 `artifacts/coverage.txt` 保存最近一次执行记录。覆盖率表中的 eval DOM 脚本不包含在 Node 的模块覆盖率里，因此不把核心模块覆盖率当作整个扩展覆盖率。

## 安装后检查

1. 设置页填写临时目标，将间隔设为 **0.5 分钟**，保存。
2. 切到已刷新的 YouTube/B 站/小红书网页，保持 Chrome 在前台，约 30–60 秒后应出现提醒。
3. 点击“再看 5 分钟”，卡片应消失；打开工具栏 popup 查看计时状态。
4. 切到非目标网页/其他应用，计时应暂停；短暂返回继续，离开满 5 分钟后从零开始。
5. 设置页点击“预览下一种提醒”，检查目标、导入项目和鼓励轮换。
6. 设置页展开“本地检查与数据管理”，点击“检查扩展运行状态”，确认定时检查和后台连接正常。
7. 将间隔恢复为 **15 分钟**，改成自己的真实目标。

## 已知边界

- 不检测桌面微信、其他浏览器或手机；不判断观看内容是否与工作有关。
- 不是精确到秒的系统计时器。Chrome 的调度、节能模式、休眠可能延迟提醒。
- 超过 90 秒的异常观察间隔不补计，避免将休眠误算成浏览。至少 5 分钟的异常间隔会开启新一轮。
- 后台视频不计；画中画视频不作为“闲置时仍观看”的信号。
- 网页容器全屏可显示卡片；原生 video 元素全屏时延迟到退出全屏。
- 巨型仓库的目录枚举由 Chrome 完成；文件选择器枚举过程中扩展无法取消，开始文本读取后可以取消。
- 学校/公司策略可能禁止开发者模式；遇到这种限制需由管理员允许，不应绕过管理策略。

## 自定义监控网站（0.2.0）

打开插件 →「目标与设置」→「哪些网站需要提醒？」。每行一个域名或完整 HTTP/HTTPS 网址，点击「保存网站列表」并允许 Chrome 的网站访问请求。支持最多 50 个网站；网址会归一化为域名，忽略路径和端口，包含子域名。删除一行并保存即停止监控该网站；清空后不监控任何网站。默认列表为 YouTube、B 站、小红书，旧配置自动兼容。

所有选择的网站合并累计；学习模式、前台判断、连续离开 5 分钟重置规则保持不变。网站列表保存后本轮清零。Chrome 内部页面、扩展商店等受保护页面不支持。新增网站通过可选权限按域名申请，不默认授权所有网站。删除列表项停止匹配及后续动态注入，但不会撤销 Chrome 中已授予的访问权限；权限可在 Chrome 扩展详情中管理。

0.2.1 起，网站列表默认以已保存标签展示。点击「编辑网站列表」修改，保存成功后自动收起输入框；点击「取消」保留原配置。
